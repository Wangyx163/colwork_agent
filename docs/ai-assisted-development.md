# AI-Assisted Development

本项目在开发阶段使用多个AI编码工具，但运行时产品模型与开发工具严格分开。开发工具不进入生产依赖，也不成为权限、状态或评测事实源。

## 开发工具分工

| 工具 | 主要用途 | 原因 |
|---|---|---|
| ChatGPT（GPT-5.6 Sol） | 描述需求、挑战假设、起草SDD | 适合把业务目标和约束转成结构化问题与设计文档 |
| Claude Code | 优化SDD、检查跨文档一致性、搭建早期架构 | 适合长文档和跨文件结构分析 |
| Codex（GPT-5.6 Sol） | 核心领域架构、状态机、数据库、Outbox与恢复实现 | 用于涉及跨模块不变量和较高失败代价的任务 |
| Codex（GPT-5.6 Terra/Luna） | 规则明确的实现、测试、UI和机械回归 | 已有明确oracle的工作不需要持续使用最高推理档 |

## 人与开发AI的分工

项目负责人负责：

- 定义业务目标、优先级和数据授权边界；
- 决定什么应成为任务、hint或人工判断；
- 挑战窗口、指标、阈值和架构假设；
- 审核实验解释并承担最终产品判断。

开发AI负责：

- 阅读代码和拆解链路；
- 提出实现与反对意见；
- 编写代码、测试和评测运行器；
- 运行实验、定位失败样本并维护设计文档。

## 使用纪律

1. 权限、状态、计分、lineage和恢复必须有确定性oracle。
2. 高推理模型用于跨模块设计，低成本模型用于边界清楚且测试充分的实现。
3. AI生成的专业表述不能替代真实测试、人工标注或外部环境验证。
4. 开发Agent的私有记忆、Token路由和阶段性TODO不作为公开项目文档。
