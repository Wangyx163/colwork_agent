# N13｜最小角色工作台

版本：2.0  
变更依据：ADR-029、ADR-030、ADR-031、ADR-034、ADR-035

## P0

P0 保留同事任务页、负责人管理页和开发诊断页，但三个页面必须使用服务端角色 projection：

- 共享顶部：Episode 状态与任务完成聚合；不展示手动刷新按钮，不使用高频轮询。首次进入和用户完成显式动作后，只重新读取受影响页面状态，表单草稿在成功前必须保留。
- 同事页右上角以闹铃和未回应数量承载派发任务；点击后在按钮下方打开 Popover，可留言并接受或退回重改，不跳转页面。
- 同事页将本人负责与协作中的任务整理为一条活跃时间线：负责为蓝色、协作为紫色；点击任务时外框高亮、其他任务降低透明度，下方任务执行区切换到该任务。历史参与任务不进入活跃时间线，在后部折叠展示。
- PARTICIPANT 只读取自己的任务明细、同任务成员角色/回应状态以及会议级聚合进度；COORDINATOR 才读取完整团队工期和个体风险。不得向普通参会者展示其他人的个人承诺、进展、阻塞、提交正文或 `management_review_policy`。
- 任务复核卡与任务卡必须展示 `SOLO` 或协作者，并区分“负责人/我以协作者参与”；协作者不是共同 owner，但在有效协作期拥有同一任务的进展与交付权限。
- 同事任务页的负责/协作任务共用同一选中任务执行区和协作记录；只有负责人显示个人承诺修订和贡献处理按钮。表单草稿在提交成功前本地保持。
- 协作者提交按钮/回执必须明确“提交协作成果，不结束整项任务”。负责人在原任务卡查看每个贡献版本及 `CONTRIBUTION_ANALYSIS`，并选择“纳入任务资料/要求补充/作为最终候选送验”；已处理版本不得继续显示处理按钮。
- 贡献版本确定性校验失败时显示“校验未通过”和可重交原因，不得计入“等待负责人处理”，也不得出现负责人处理按钮。
- 协作记录必须合并展示承诺、所有贡献者的快捷状态、邀请/确认/解决/取消、贡献接收、负责人处理、最终候选和人工验收，并使用事实事件时间排序；协作者交付需标明真实提交人，不允许出现独立的“协作系统”时间线。
- 负责人管理页：任务复核发布、团队日期、工期冲突、全部贡献与负责人处理、进入 PENDING_ACCEPTANCE 的最终候选、完整验收辅助包、AcceptedTaskResult、FINAL_RELEASE 与终稿 lineage。待验收卡同时展示真实提交人和任务负责人。
- 协作 Memory：本人可查看预制词条候选，并执行确认、同 topic 替换或拒绝；不提供自由文本词条和展示偏好设置。负责人只看本次任务事实型协作报告。
- 开发诊断页：5 个 GATE、FLOW/EFFECT/NODE SIGNAL、AuditEvent 和 Outbox 证据，不向普通业务页面暴露。

P0 没有 L3/直属上级审批卡。重复提交、验收和 FINAL_RELEASE 由 API 幂等保护；UI 的可见/隐藏不是授权依据。

- 验证：MANUAL-N13-001 至 MANUAL-N13-006、AUTO-N13-007 至 AUTO-N13-010。

## P1

- 筛选、失败详情、归档下载、消息合并解释和更细状态视觉。
- 经过身份 Adapter 映射的飞书卡片入口；页面只作为补充工作台。
- 协作结构卡只展示负责人复核后的白名单模板、成员、阶段、等待对象、完成计数和最终负责人；不得把参与者渲染成共同 owner。
- 下游等待态必须说明“在等谁的哪一个已验收结果”；上游版本变化导致下游失效时，展示旧 lineage 与需要重新确认的范围。
- 多人参与决策必须分别展示候选提交、参与记录、确定性汇总结果和最终负责人定稿，不能把投票结果直接当成终稿验收。
- 最终负责人只看到已验收上游结果；点击后由 Agent 生成带来源的 ballot 草稿，可删选和改字，显式确认后发布。页面展示 `generation_mode/model/prompt_version`，模型失败但规则降级时不得伪装为模型成功。
- 投票人对全部候选给 1–5 分，提交按钮必须明确“提交后不可修改”；ballot 发布后同样锁定。指定投票未齐时，最终提交按钮由服务端 Gate 阻止，而不是只靠 UI 隐藏。
