# 会议行动项标注规范 v1.0

## 0. 这份标注是干什么的

AMC-A（AliMeeting4MUG）只能测**它自己的口径**：「任务描述 + 时间框架 + 负责人」同时出现的句子。
我们的产品口径不同——抽任务不要求句内有时间，缺了就标 `needs_confirmation` 交负责人补。

所以 AMC-A 上的分数（held-out F1 0.13）**测的不是我们要做的事**。这份标注是唯一能回答下面这些问题的证据：

- 我们抽出来的东西，负责人真的需要吗？
- 过抽 2.5 倍，是"有用地多抽"还是"噪音"？
- 漏掉的那些，是产品有意排除的，还是真漏了？

**因此：按"你作为会议负责人，希望系统把哪些东西端到你面前复核"来标，不要去猜 AMC-A 会怎么标。**

---

## 1. 标什么：两种类型

### TASK —— 会后要做出东西或完成动作，有可交付物

> 「小王明天把访谈问题清单发给我」→ 交付物：访谈问题清单
> 「找个设计公司把海报做出来」→ 交付物：海报设计

### COMMITMENT —— 本次会议当场约定的时间节点，本身没有产出物

> 「争取后天我们就再拍板」→ 节点：完成方案拍板
> 「这月底三十号一大早出发」→ 节点：团队出发

COMMITMENT 必须**同时**满足三条，缺一不标：

| | 条件 | 反例 |
|---|---|---|
| a | 原文含明确时间点或期限 | 「尽快搞定」——没有具体时间 |
| b | 是本次会议**当场做出的约定** | 「我们下个月要办活动」——会议前提，不是当场约定 |
| c | 承诺主体是本次与会方 | 「供应商说下周发货」——第三方 |

---

## 2. 明确**不标**的四类

这四类是产品决策，不是遗漏。标了会让评测失真。

| 类别 | 例子 | 为什么不标 |
|---|---|---|
| **会议前提 / 背景** | 「今年我们公司要组织员工出去游玩」<br>「上次跟你提过，我们下个月准备办相亲活动」 | 是会议**为什么开**，不是会议**产出什么**。它已经是既定事实，不需要谁去执行 |
| **惯例 / 流程描述** | 「早上男方要去接亲」<br>「北方一般六七点前要把女方接出来」 | 在描述事情通常怎么办，不是本次指派给谁 |
| **模糊意向** | 「近期可能要办一些活动」<br>「这块儿我们后面也可以看看」 | 含「可能／大概／也许／再说」等，没有形成承诺 |
| **会中已完成的动作** | 「我现在就把文档发群里」（且当场发了）<br>「我查一下……好了，是 3 号」 | 会议结束时已经完成，没有待办 |

**判断口诀**：会议结束后，**有没有一件事还需要某个人去做？** 没有就不标。

## 3. 边界情况怎么办

| 情况 | 怎么标 |
|---|---|
| 一句话里两件事（「你做 A，他做 B」） | **标两条**，`source_quote` 可以是同一句 |
| 一件事分散在几句里 | **标一条**，`source_quote` 选**最明确说出这件事**的那一句 |
| 有人布置、另一人只答「行」 | 标一条，引**布置任务的那句**，不引「行」 |
| 讨论了几个方案，最后定了一个 | 只标**定下来的**那个 |
| 说了要做但没说谁做 | **照标**，`owner_name` 填 `null`（这正是系统要交给负责人补的） |
| **原文说了两个人一起做**（「小蒲和袁浩去改」） | `owner_name` 填原文里**最先或最明确被指派**的那个，其余进 `collaborator_names`。**不要因为有两个人就填 null** —— 抽取器能表达这种关系，填 null 会把正确抽取判成错 |
| 原文说「每个人／大家」 | `owner_name` 填 `null`，`collaborator_names` 留 `[]`。这类任务本来就要负责人逐个派发，null 是正确表示 |
| 说了要做但没说什么时候 | **照标**，`deadline_*` 填 `null` |
| 你自己拿不准 | **标上**，并在 `annotator_note` 写一句为什么犹豫 |

最后一条很重要：**拿不准的记下来，不要静默丢弃。** 这些边界样本本身就是结论的一部分——AMC-A 的标注者间 Kappa 只有 0.47，说明这件事本来就主观，诚实记录分歧比假装没有分歧有价值。

## 4. 文件格式

放在 `fixtures/` 下，例如 `fixtures/meeting_gold_20260310.json`：

```json
{
  "schema_version": "annotation.v1",
  "description": "真实会议人工标注；用于产品口径抽取评测",
  "cases": [
    {
      "case_id": "acisc-20260309",
      "meeting_date": "2026-03-09",
      "participants": ["王昱翔", "宋潽暄", "黄Z恒", "绒", "Jasmine"],
      "blind": false,
      "transcript": "王昱翔(00:00:00): 今天我们讨论街采的事。\n绒(00:01:12): 那我这边准备七八个采访问题发给子恒。\n",
      "expected": [
        {
          "title": "准备街采候选问题",
          "item_type": "TASK",
          "deliverable": "7—8 个候选采访问题",
          "owner_name": "绒",
          "collaborator_names": [],
          "deadline_text": null,
          "deadline_iso": null,
          "source_timestamp": "00:01:12",
          "source_quote": "那我这边准备七八个采访问题发给子恒。",
          "annotator_note": ""
        }
      ]
    }
  ]
}
```

### 字段说明

| 字段 | 必填 | 说明 |
|---|---|---|
| `case_id` | ✅ | 会议唯一标识，评测报告里按它归类 |
| `meeting_date` | ✅ | `YYYY-MM-DD`，用于把「明天」解析成绝对日期 |
| `participants` | ✅ | 参会名单。**系统不从正文猜人**，这是权限边界 |
| `blind` | ✅ | `true` = 这份从未用于调 Prompt 或规则，**最终报数只用 blind 的** |
| `transcript` | ✅ | 逐字稿全文，格式 `说话人(HH:MM:SS): 内容` |
| `title` | ✅ | 简短任务名，你自己的话，不必逐字来自原文 |
| `item_type` | ✅ | `TASK` 或 `COMMITMENT` |
| `deliverable` | ✅ | 可验收的交付内容。COMMITMENT 填节点的中性描述 |
| `owner_name` | ✅ | 原文明确说了才填，否则 `null`。**必须是 `participants` 里的名字** |
| `collaborator_names` | ✅ | 原文明说「甲和乙一起做／乙配合甲」时填其余人，否则 `[]`。也必须在名单里，且不能和 owner 重复 |
| `deadline_text` | ✅ | 原文里的时间说法（「明天下午五点前」），没有填 `null` |
| `deadline_iso` | ✅ | 能唯一确定才填 ISO-8601，否则 `null` |
| `source_timestamp` | ✅ | `HH:MM:SS`，**必须是逐字稿里真实存在的时间戳** |
| `source_quote` | ✅ | **逐字复制原文一句**，不要改写、不要拼接 |
| `annotator_note` | ⬜ | 犹豫的原因、分歧点 |

### ⚠️ 三条最容易出错的

1. **`source_quote` 必须逐字**。评测靠它把标注定位回逐字稿——改一个字就定位不到，这条标注等于作废。**直接复制粘贴，不要手打。**
2. **一条标注对应一句**。不要把两句拼成一个 quote。一件事跨句就选最明确那句。
3. **`owner_name` 和 `collaborator_names` 都必须在 `participants` 里**，且同一个人不能既是 owner 又是协作者。

## 5. 需要标几份

| 用途 | 份数 | `blind` |
|---|---|---|
| 开发回归（可以看、可以据此调 Prompt） | 1–2 | `false` |
| **最终盲测（标完就锁，不看内容不调参）** | **至少 1** | `true` |

**盲测那份是整个评测可信度的来源。** 标完之后不要打开看抽取结果，直到最终报数那一次。

每份会议大约 30–60 分钟。**不需要逐句标**——只标"应该有哪些行动项"，一场会议通常 3–10 条。

## 6. 标完怎么验

```powershell
$env:PYTHONPATH = "src"
.venv\Scripts\python.exe -m collab_agent check-annotation --cases fixtures\meeting_gold_20260310.json
```

校验器会检查：引文能否逐字定位、时间戳是否存在、owner 与协作者是否在名单内且不重叠、item_type 是否合法、是否有多条标注撞到同一句。

**全绿之后再交给我**，否则评测跑出来的数字是错的。

## 7. 我不会做的事

- **不会**根据抽取结果反过来调整你的标注——那是自己给自己出考卷
- **不会**把你标了但我们没抽到的条目从金标里筛掉——那是挑对自己有利的算法
- 分歧会如实报告，不会藏
